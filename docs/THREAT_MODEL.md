# CLI Application Threat Model

The owner trusts the installed application, Python runtime, operating system, cryptographic library and optional local-model server. Input events are untrusted. Network access is unnecessary except for an explicitly configured loopback model. The main assets are raw history, derived memories, keys and cloud-policy integrity.

| Required scenario | Risk and impact | Implemented mitigation and residual limits |
|---|---|---|
| Host process / file compromise | Another user, stolen backup or malicious process reads keys, credentials or private history. | Dedicated owner-only directory and files, Windows protected ACLs, AES-GCM raw envelopes, OS keyring or scrypt-wrapped key, short raw retention. Memory/FTS and metadata remain plaintext. Same-user malware, administrator access, process-memory inspection and malicious keyring backends remain outside the protection boundary. |
| Contextual prompt injection | Stored text asks a model to reveal history, change policy or call tools. | Control-character removal and injection flags; content is always data. Optional model sees a delimited JSON user message, not interpolated system instructions. No tools, fixed loopback destination, schema validation, fallback and raise-only classification. Router never accepts a model's policy decision. Model hallucinations and malicious external server behavior remain possible. |
| Implicit cloud exfiltration | A query, app/source label or generated entity carries sensitive data past a content-only filter. | Classify content and metadata, check derived text, route on maximum query/result tier, strict flags and deny on errors. No cloud transport exists. Future payload preparation allowlists only redacted summary/topics/tier and strips detected/known people. Heuristic redaction is not a proof of anonymity or detection of every credential format. |
| Sensitive leakage in diagnostics | Secrets appear in exceptions, argument parsing errors, logs or terminal history. | Generic safe errors, no tracebacks by default, static diagnostic event codes with validated IDs, value-free evidence and content-free audit. Ingest prints counts/IDs; search/show print intentionally requested redacted memories. Passphrases are prompted, not arguments; the UI masks them and keeps them out of command history. Redacted memories can still contain private names/context, and heuristics can miss unknown secret formats. Query/reason command arguments can still enter the user's shell history, so never put actual secrets there. |
| Unintentional context capture | A watcher collects password-manager, keychain or concealed clipboard content. | No passive watcher, keyboard hooks or screen capture. Explicit JSON ingestion or typed notes only, app/source filters before extraction, `--drop-secrets`, read-only previews and retention maintenance. This does not inspect OS clipboard concealment flags because no live clipboard reader is implemented. |

Additional controls include parameterized SQL, quoted FTS tokens, strict size limits, type checking, UTC validation, transaction rollback, integrity diagnostics and deletion of FTS/evidence/entity links. Settings parse errors disable cloud eligibility. Public source matching validates origin and path boundaries rather than substring matching. Public source allowlisting never overrides detected secret/personal/business evidence.

An explicit sensitivity downgrade is recorded and requires `--confirm-lower`. Corrections are not silently generalized into looser rules. Settings are owner-editable; a same-user attacker who changes the binary/policy is not stopped by a settings hash. Audit is for explanation, not a tamper-proof forensic ledger.

Secure-delete and VACUUM remove logical records and reduce recoverable SQLite content. They cannot erase SSD wear-leveling blocks, OS snapshots, old backups, swap or crash dumps. A wipe of passphrase metadata cannot invalidate copies of that metadata and encrypted raw files retained elsewhere. Per-day key crypto-shredding and full encrypted-index deletion are future designs, not current guarantees.

The tests plant synthetic canaries across content, metadata, summaries and error paths. Passing them establishes behavior for that corpus; it does not establish universal secret recall, regulatory compliance or production security certification.
